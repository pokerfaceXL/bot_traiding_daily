# Outcome

A frozen validation protocol (`spec/research/F005-validation-protocol.md`: 5-symbol basket chosen by liquidity only, 4h/1h, 30-month train/validation/holdout windows with correct warm-up buffering, holdout untouchable rule binding on all future features) and a measured baseline (`spec/research/F005-baseline.md`: all 79 catalog strategies × 5 symbols × 2 intervals, 790 runs, real Bybit data) now exist, as required before any new-strategy search.

**The baseline result is a hard failure, verified genuine, not a bug**: 0 of 24,885 valid months meet the ≤20% deviation target anywhere, and 790/790 combinations exceed the 50% max-drawdown hard rejection criterion. Root cause, confirmed by hand-inspecting raw trade sequences myself: at `configuration/default.yaml`'s existing `leverage=10` with `equity.py`'s `margin=stake=$100` contract, a single stop-loss (`max_sl_pct=0.03` on $1000 notional) costs ≈$30-33 — roughly a third of the margin risked per trade. With `cooldown_candles=0` and realistic win rates, ~12-15 losing trades exhaust the shared $500 portfolio below the $100 re-entry floor within 1-3 months, after which the account can never trade again for the remaining ~27 months. Final equity across all 790 runs lands in a suspiciously narrow $66.86-$99.96 band — confirming one systemic mechanism, not strategy-specific noise.

**This blocks a meaningful start to F006** as currently scoped: searching for new signal ideas is pointless while every strategy — old or new — dies to the same leverage/sizing mechanism before validation even begins. Leverage is a risk limit, and `spec/build.md` reserves risk-limit changes for the owner. Flagged prominently for her return; a supplementary leverage-sensitivity diagnostic (pure measurement, not a production change) is running to hand back more complete evidence for that decision.
