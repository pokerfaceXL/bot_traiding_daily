# Outcome

`backtest_apex.py`'s default (non-`--param-optimization`) path now runs through a new, cost- and equity-aware engine instead of `strategy.py`'s free `_make_trade` calculation: `costs.py` (commission/spread/slippage/funding), `equity.py` (shared 500 USD portfolio, margin rejection, mark-to-market drawdown), `execution.py` (next-bar-open fills, conservative worst-case intra-bar SL/TP ordering, gap-through-stop handling), composed by `backtest_engine.py` into `run_backtest()`. A discriminating integration test proves the CLI's reported PnL is strictly lower than the old free engine's, by an amount that reconciles exactly to the sum of applied costs — not just "different." 63 tests pass. `--param-optimization` (Optuna) still calls the old free engine — documented as an explicit follow-up gap, not silently dropped.

Built and merged in five reviewed waves; every wave was independently re-run and spot-checked against hand-calculated numbers before merging, not just trusted from the worker's own report. Two real defects were caught and fixed in review: a `strategy.py` import-time `sys.argv` side effect that broke `pytest tests/` (fixed via `tests/conftest.py`, `strategy.py` itself untouched), and a `profit_factor` no-losses sentinel that Coordinator's own wave-5 instructions got backwards (`0.0` instead of matching `strategy.py`'s `9999.0`) — corrected after merge, comment trail kept in `backtest_engine.py` and `spec/research/F004-execution-equity.md`.
